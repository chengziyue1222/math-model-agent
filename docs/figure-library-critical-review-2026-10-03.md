# 数学建模图表库全面审查与锐评

审查日期：2026-10-03  
审查对象：`code/algorithms/figures/`、154 项注册表、全量随机预览、精选学术风格画廊

## 一、结论先行

当前图表库已经具备完整的中文目录、统一导出格式和一套质量较高的精选学术图。但“154 个可调用名称”与“154 个语义独立、可以直接用于论文的图型实现”仍不是一回事。

全量预览已经能运行，视觉上也比最初版本丰富；然而注册表中仍存在大量适配器和别名，部分图型只是换标题或换少量编码。把所有条目标成 `implemented and reusable`、`paper_suitable=True`，会掩盖实现层级差异，这是当前最需要纠正的治理问题。

## 三、视觉锐评

### 做得好的地方

1. 精选 24 图已经接近可用于论文草图的质量：配色克制、中文字体可读、图例和直接标签基本清楚。
2. ROC、相关矩阵、山脊图、气泡图、网络图、弦图、Mantel 图、小提琴图、响应面和 XPS 分峰等高频图型有明显的学术风格。
3. 全量导出保留 PNG/PDF/SVG 与 `.figure.json`，这对追溯数据来源和导出设置很有价值。
4. 预览中已经加入原始点、区间带、正负边线型和颜色语义，方向是对的。

### 主要问题

#### 1. 图型语义仍有“标题欺骗”

某些图的标题叫“响应面图”“帕累托前沿图”“敏感性曲线”，图面却仍是二维折线、散点或普通等高线。形式看起来像，统计含义却没有实现。论文中这会造成读者误读，尤其是响应面、帕累托、Taylor、SHAP、校准和空间图。

#### 2. 154 项的实现等级没有诚实表达

目前 154 项全部标记为 `implemented and reusable`，118 项只登记了 `values`。这表示 API 能画出来，不表示它拥有正确的数据结构、统计计算或图型语义。图表库应该区分：

- 专用统计实现
- 学术风格适配器
- 兼容别名
- 仅用于版式预览的模板

#### 3. 单位、区间和独立单位不稳定

很多预览轴名仍是“指标值”“响应值”“参数/情景”，没有从 `DataContract` 强制取单位；误差棒、预测带和置信区间也没有统一要求 `interval_kind`。这在数学建模论文中会直接降低可信度。

#### 4. 网络、流量和空间图的真实数据契约不足

网络图应该要求 `nodes/edges/weights/community` 等字段，桑基图应该要求 `source/target/value`，空间图应该要求 `longitude/latitude/value`。现在不少入口仍可用一维 `values` 代替，导致图能生成但不代表用户实际要表达的结构。

#### 5. 精选页比全量库成熟太多

精选 24 图明显优于全量 154 图。全量库目前更像“目录覆盖 + 视觉适配器”，还不是 154 个完成度一致的论文图型。应避免用精选页的质量代表整个库。

#### 6. 预览数据不能验证统计正确性

随机数据只能检查版式和代码路径，不能验证 AUC、相关系数、区间、聚类、显著性、权重或空间投影是否正确。当前所有预览都标记为 `NOT_CHECKED`，这是正确的，但也说明还没有完成最终验收。

## 四、改进优先级

### P0：先纠正注册表和契约

1. 给 `FigureSpec` 增加 `implementation_level`：`dedicated`、`adapter`、`alias`、`template`。
2. 把 8 对精确重复拆开；如果确实是兼容别名，就在目录中明确显示“别名”，不要标成独立实现。
3. 为每个图型登记真实字段和校验器，例如：

   - ROC：`y_true`, `y_score`
   - PCA 双标图：`scores`, `loadings`, `explained_variance`
   - 响应面：`x_grid`, `y_grid`, `z`
   - 桑基：`source`, `target`, `value`
   - 空间气泡：`longitude`, `latitude`, `size`, `group`
   - 森林图：`estimate`, `lower`, `upper`, `interval_kind`

### P1：优先完成 30 个高频专用实现

优先顺序建议为：

1. 柱状/分组/堆叠/森林/误差棒
2. 散点/回归/联合密度/六边形分箱/火山图
3. 热图/相关矩阵/混淆矩阵/转移矩阵
4. ROC/PR/校准/残差/学习曲线
5. PCA 双标图、载荷图、碎石图、t-SNE、UMAP
6. 响应面、灵敏度、帕累托、龙卷风、稳健性包络
7. 网络、桑基、弦图、空间气泡、3D 结构

这些实现要有真实的数据计算，而不是只改变颜色或标记。

### P1：建立真实数据夹具

从 `E:\数据要素` 选取经过脱敏的代表性数据，按图型家族建立 10–15 个固定夹具。每个夹具同时验证：数值、标签、单位、区间、图例和导出元数据。随机预览继续保留，但只能叫“版式预览”。

### P2：统一视觉系统

1. 统一字体回退、字号、线宽、图例位置和标题层级。
2. 对长标签自动换行或外置，避免压缩绘图区。
3. 黑白打印和色盲模式各做一次 QA。
4. 论文成品默认去掉“随机数据预览”字样；随机字样只留在预览页面和元数据中。

### P2：增加自动质量门禁

- 精确重复检测：除明确别名外，禁止相同 PNG。
- 结构检测：响应面必须有二维网格或 3D 曲面，桑基必须有流带，森林图必须有区间，网络图必须有边。
- 语义检测：轴标签、单位、区间类型和图例必须与 `FigureSpec` 一致。
- 导出检测：PNG/PDF/SVG、字体、灰度和 metadata 全部通过后才能标记 `paper_suitable=True`。

## 五、建议的最终验收标准

只有同时满足以下条件，才建议把图型标记为“论文可用”：

1. 图形结构与名称对应，不是标题替换。
2. 数据契约能拒绝缺字段和错维度输入。
3. 数值编码有独立测试，至少验证一组人工可计算的小数据。
4. 单位、区间类型、独立分析单位写入图和元数据。
5. PNG、PDF、SVG 均能打开，中文字体无缺字。
6. 至少完成一次人工视觉复核，并记录复核结果。

## 六、最终判断

现在的库适合：快速选图型、生成版式草图、在建模过程中调用统一的绘图入口。  
现在的库还不适合：不经人工检查就把 154 张图全部当作论文终稿，或把所有注册项都宣传成独立的统计实现。

下一轮最值得做的不是继续增加图型数量，而是把实现等级、数据契约和统计语义补齐，优先消灭精确重复和“看起来像但含义不对”的图。
